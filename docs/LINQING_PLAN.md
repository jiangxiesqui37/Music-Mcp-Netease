# 霖卿音乐屋改造计划

> 基于 `Anko3o/Music-Mcp-Netease` 的私人自托管改造。
> 当前阶段只做规划与基线记录，不部署、不填写 `MUSIC_U`、不开放公网 MCP。

## 核心目标

做一个只服务卿卿和老公听歌的私人播放器。网易云只作为曲库、歌单、歌词、封面和必要账号数据来源，不复刻网易云社交主页。

## 保留

- 搜歌与播放
- 红心歌曲与歌单读取
- 日推
- 歌词、封面、评论、MV（按实际使用情况保留）
- 播放队列
- 本地歌单与共同歌单
- MCP 点歌能力

## 前台不展示 / 后续可删

- 关注、粉丝
- 等级、听歌时长等社交资料
- 装扮、动态、社交主页
- 播客、笔记、会员中心
- IP 属地
- 充值 / 会员营销入口

## 计划新增

- `qingqing` / `linlin` 双住户身份
- 一起听 / 共同队列
- “谁点的歌”“点给谁”
- 共同收藏与歌词小纸条
- 设备标识与设备定向播放
- MCP：当前歌曲、暂停、继续、上一首、下一首、进度、音量、队列、设备选择

## 安全优先项

1. `server` 与 `mcp` 默认只监听 loopback。
2. `MUSIC_U` 只保存在服务器端，不进入前端、仓库或日志。
3. 首轮测试尽量只读，暂缓红心写回和 scrobble。
4. 公网 MCP 上线前补独立认证、Origin 校验、限流与最小权限。
5. 先单设备验证，之后再重构 remote 队列，避免多设备抢消费。

## 第一里程碑

先不改 UI，只验证：

1. VPS 上原版安全启动。
2. 平板可以打开 Web 播放器。
3. 能读取完整红心 / 歌单数据。
4. 能正常播放一首歌。
5. MCP 能安全地给指定测试设备点一首歌。

完成这五项之后，再开始 UI 和双住户改造。

## 分支约定

- `main`：尽量保持接近上游，方便同步。
- `dev/linqing`：霖卿音乐屋的开发分支。
